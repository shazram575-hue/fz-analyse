## 开始任务

1. 读AGENTS、科研进度的结论/导航及相关方向记录。根据当前目标定向读实际代码、日志和结果；其他聊天内容不可假定存在。
2. 若为Git工作区，记录起始分支、HEAD、工作区状态和实际可核实的远端/审核合并依据。不自动拉取、切换、重置或清理他人修改；落后/分叉时说明基线。无Git、离线或凭证不足时明确记录，不自行初始化仓库。
3. 分别写明任务授权、证据读取范围与未核实项。已查看代码不等于已运行，完成标记不等于科学验证成功。先检查可复用结果，避免重复主体计算。

## 三种状态分别记录

- **计算状态**：未开始、运行中、部分完成、完成、失败或停止；附真实日志/产物/断点。未来任务只记录自己可确认的后台任务状态，不替其他任务宣布“无任务”。
- **科学状态**：探索性/预先指定验证、支持范围、阴性/不精确/方向冲突、统计与技术限制。结论必须能追溯到输入、方法和结果，不从计算完成推导假设成立。
- **同步状态**：按下表记录；模型、代码、文档及外置数据可有不同同步状态，不能一并概括为“全部已同步”。

| 状态 | 含义与必要依据 |
|---|---|
| `LOCAL_ONLY` | 仅本地或未提交修改。2026-10-26接手记录的非仓库状态是历史快照；最新Git实况按2026-10-27同步日志及当前checkout核实。 |
| `BRANCH_UNMERGED` | 已有提交或推送，但尚无已审核合并证据；即使直接推送集成分支，也不自动标记科研状态已审核。记录可核实的分支/commit/PR，其他任务须识别待审范围。 |
| `MERGED_REVIEWED` | 已审核、提交并合并到GitHub约定集成分支。记录目标分支、PR或审核记录、合并commit及核实来源；只有此状态可纳入已共享最新科研状态。不能假设分支一定叫main。 |
| `UNVERIFIED` | 无法核实位置、提交、审核或合并等必要信息。标明缺哪项，不能自动升级。 |

记录“读取的已共享基线”和“本任务新增修改状态”，不要混为一项。时间戳、文件名、测试通过、完成标记、PR打开或仅本地commit均不足以升级为`MERGED_REVIEWED`。即使代码已合并，Git忽略的大对象仍需单独提供位置、访问条件和校验；没有恢复就不称云端可用。

## 进展、并行与收尾

- 实质进展先写自己的唯一任务日志，再给方向记录和RESEARCH_PROGRESS添加简短入口/状态变化。保存输入输出、参数、种子、校正范围、软件版本、实际命令与验证结果；记录失败及阴性结果，不覆盖旧证据。仅文档任务明确“无新科学计算”。
- 多任务优先修改各自日志和授权范围内文件。修改共用进度入口前读最新内容，只合并本任务增量，保留其他任务条目；有冲突依据源文件、冻结规则和审核决定解决。不得把另一分支未合并结果当主线事实，也不得把本任务建议作为其他任务授权。
- 建议被接受、用户批准执行、计算完成、审核合并是不同事件，分别记录。任何结论修订说明依据和旧结论位置；禁止通过选患者/参数追求显著性。
- 完成/中断时填全交接模板，特别写清还没做什么、不可估/失败原因、后台进程/断点、可恢复命令及下一步所需授权。没有进程信息则写“未核实”。
- 未获明确授权，不提交、推送、建PR或合并；不执行强制推送、重置或清理他人工作。获授权提交也不等于获授权合并。交付日志即使未同步也须保留，并标`LOCAL_ONLY`或`BRANCH_UNMERGED`。
- 后续审核合并经核实后，在任务日志追加“同步确认”及证据，更新全项目入口。保留最初LOCAL_ONLY快照，不追改成当时已同步。日志不要求填写包含自身最终文本的commit：未知写未知，可在后续任务用真实PR/合并记录补确认，避免循环造提交。

本机制依靠仓库中的文档和可核实Git记录，不能自动传递未提交文件、外置数据或其他聊天记忆。
